## Model-drift bug: `content[0]` indexing broke on claude-opus-5

`d151dc3`. Not a coding error against the model the code was written for — `claude-opus-5`
runs adaptive thinking ON BY DEFAULT (unlike opus-4-7/4-8), so `msg.content[0]` could be a
`ThinkingBlock` with no `.text`, raising `AttributeError` inside the existing retry/except,
which silently reported every affected call as a generic failure while the API itself
returned HTTP 200. Fixed by selecting the text block by `.type` rather than position;
`stop_reason == 'refusal'` and thinking-only responses are now explicit failure states
rather than empty successes. New `test_response_blocks.py` stubs the SDK and drives the real
parsing path against all four shapes; `test_chat.py`/`test_authority.py` re-run clean to
confirm no regression on the shared path. **Confirmed via tree-wide grep this was the ONLY
`.content[0]` indexing site and the ONLY `messages.create()` call site in the whole
codebase** — every AI surface in the product routes through this one function, so the fix
covers the whole product, not one call site.
