## Arc of the day

Smaller commit count than yesterday (9 vs. 42) but higher-stakes: today closed out the
live tailnet-block defect found in yesterday's Phase 1 verification, finished the
host-defense punchlist, and started real build work on ADR 0019's enforcement table.

1. **Host-defense punchlist fully closed.** The fail2ban end-to-end ban test that was
   blocked yesterday (no sudo grant, no expendable test IP) ran successfully today —
   independently confirmed via `audit_log` (three ban/deny cycles against `203.0.113.7`,
   an RFC 5737 test address, each correctly attributed to `fail2ban` and cleanly expired by
   `alert-watcher` afterward). `MAX_BUCKETS` tightened to the validated 256 (pinned in
   `hw-monitor.service`, code default stays 4096 as the wider fallback). Step 7's ufw
   hardening landed **and was done the careful way**: `LIMIT` rules on 22/tcp and 80/tcp,
   both scoped to `<lan-subnet>/22`, correctly *replacing* the old plain `ALLOW` rules
   (independently verified via `ufw status verbose` — the naive-append trap the original
   staged script would have fallen into was avoided). No rule added for 443 or 5000 — both
   still hit default-deny, exactly as recommended. The deploy-lifetime sudoers grant
   (`nemesis-host-defence-deploy`) was removed by the operator once all of the above was
   confirmed.
2. **The tailnet-block defect (yesterday's Finding 1) got an interim public fix.**
   `install.sh` now ships `configure_tailnet_enforcement()` — `netfilter-mode=nodivert`
   plus replicated anti-spoof guards — and `tailscale debug prefs` on this box confirms it's
   live (`NetfilterMode: 1`). ADR 0019 gained a properly-abstracted public addendum
   recording the defect and mitigation at the architecture level. **One disclosure gap not
   yet fixed:** `install.sh`'s own code comment is far more specific than the ADR addendum
   — exact rule syntax, exact reproduction method — and it's already pushed to the public
   GitHub repo. Flagged, not resolved.
3. **ADR 0019 build work started for real.** `nemesis-fw-apply` (the lockout-failsafe tool
   — LKG snapshot, `nft -c` dry-run, revert armed before apply, `systemd-run` transient
   timer scoped to `nemesis_enforce` only) and `nemesis-fw-render` (derives an observe-only
   ruleset from ufw's live DROP rules — zero authority by construction, no rule ever
   carries a verdict) are real, tested code, not just design. A measured bug (revert firing
   at 33s against a stated 60s window, under back-to-back applies) was found, root-caused
   to transient-unit state reuse, and fixed with `systemctl reset-failed` — re-verified
   clean at 60s (61s measured). Increments 1–2 proven; increment 3 proven except the
   counter-agreement comparison against ufw over real traffic, which still hasn't been run.
4. **ADR 0020 accepted** — the agent model stays sensor-only (ADR 0009 §3 unchanged);
   cached-verdict enforcement added for disconnected operation; a binding `TunnelProvider`
   abstraction required before further agent work; building a custom transport deferred
   (net cost ~8–13 sessions for benefits mostly reachable cheaper). Evidence base is
   yesterday's Phase 1 verification findings, held private.
5. **Track C's metadata-tier build plan approved and written** — 6–9 sessions, leads with a
   hard consent gate (Requirement 0) ahead of any collection code, flags an inconsistency
   with existing ungated telemetry for an explicit operator decision rather than silently
   inheriting it.
