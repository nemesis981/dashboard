## 5. Operational notes / lessons

- **Pi-hole unattended-install quirk (PUNCHLIST).** On headless installs Pi-hole's installer
  exits at a static-IP whiptail notice -> never fully installs -> a later uninstall reports
  Pi-hole "not installed". Fix direction noted (pre-answer the static-IP prompt /
  pre-seed `setupVars.conf`). Pre-existing `install.sh` issue, surfaced by the VM audit.
- **VM audit methodology improvement:** verify DB state with **`python3`**, not the
  `sqlite3` CLI — the CLI may not be installed on a base VM (it wasn't on the test VM, which
  caused a false-negative "no tables" reading early in the audit). The product's own scripts
  already use python3, so this is an operator gotcha only.
- **Settings persist on reinstall (intentional).** Because uninstall **preserves the
  `diagnostics_*` tables by design**, a reinstall keeps the prior `watcher_enabled` state —
  so **reinstall != settings reset**. Document this for users (a reinstall won't silently
  re-disable a watcher the user had turned on, nor re-enable one they turned off).
