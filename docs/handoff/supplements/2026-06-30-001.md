## NOT FULLY TRIP-READY — two before-trip fixes found by the verify pass

1. **SECURITY — auto-approve default contradicts ADR 0011.** `api_agent_installer_generate`
   mints tokens with **`auto_approve=1`** (5 of 6 tokens in the table). The "approved" device that
   appeared (no manual approval done) was auto-approved by the **token's own flag**, not a person.
   ADR 0011 mandates **manual-approval default; auto-approve = explicit opt-in.** Must default
   `auto_approve=0`.
2. **DOUBLE-ENROLL — one device, two rows.** The installer's `_enroll` enrolls but **never persists
   the returned `device_id`** into `nemesis_agent.conf`, so the frozen agent re-enrolls ~11s later.
   Forensics: both rows share the same `stable_id` / `public_key` / source IP — the first
   auto-approved (token), the second PENDING (token spent). Fix: persist `device_id`/status from the
   installer enroll into the conf (or let only one path enroll).
