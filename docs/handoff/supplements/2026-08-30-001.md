## Elevated grants — thinning root-caused, structural fix applied

Traced the "Standing elevated grants — REVIEW FOR REVOCATION" section's disappearance via
`git log -p -- docs/handoff/HANDOFF.md`: full content at `f79f5ad` (08-26) → pointer-only at
`670ab6b` (08-27) → absent at `f20d696` (08-28) and `5086b51` (08-29). Four closeouts,
monotonic decay, despite CLAUDE.md item 7 explicitly requiring it "surfaced live every
session, not noted once and forgotten."

**Root cause:** `HANDOFF.md` is overwritten wholesale each closeout (Rule 9's "latest state
wins"). Content embedded there survives only if every closeout author remembers to manually
retype or carry it forward in full — no diff shows what was dropped, no reflog records it.
Same failure shape as the uncommitted-tracked-file hazard the 2026-08-29 "commit locally,
immediately" rule was written to close (structural gap, not vigilance gap — and vigilance
had already failed four times running here).

**Fix, matching that rule's shape (make the correct outcome the only reachable one, not a
thing to remember):**
- New file, `docs/handoff/elevated-grants-tracking.md`, **edited in place** (never
  regenerated from scratch — same discipline as `PUNCHLIST.md`). A file that's edited
  rather than overwritten cannot lose content nobody touched, because there's no rewrite
  step where a section can go silently missing from "the new version."
- Populated with this session's live findings: production box confirmed clean (no broad
  grants, no `nmap`), `pihole` still open (unchanged, tracked for the cardinality tool),
  gateway-VM `nmap` grant carried forward **explicitly marked not re-verified today** (last
  confirmed 2026-08-26 — Morning Status checks the build host, not fleet VMs; the open
  scope question about extending it to fleet VMs is restated, not silently dropped a second
  time), polkit rules unchecked (permission denied, needs root — noted per the existing
  instruction to flag rather than skip).
- `CLAUDE.md` item 7 amended: now instructs updating the tracking file directly, and
  explicitly forbids embedding the detail in `HANDOFF.md` again, with the four-closeout
  decay documented as the reason.
- `HANDOFF.md`'s own section is now a one-line pointer + current-state summary — cheap
  enough to keep accurate every closeout, and if it does go stale, the detail behind it
  hasn't (it isn't re-derived from the pointer).
