## Theme 2 — The V2.0 gap-scan, twice

Ran a full scoping pass (4 parallel research forks) to find every feature shipped short of
its intended design, across Linux + Windows, distinguishing V2.0 gaps from V3.0-scope items
(Apple/macOS, Windows Server, general polish — explicitly out per the operator's directive).
Full report: `~/work/nemesis-internal/audits/v2-gap-scan-2026-08-23.md`.

One finding (item 4, malware Layer-C verdict rendering) turned out to already be fixed
before the scan even ran — it trusted a stale PUNCHLIST entry instead of the code. That
prompted a second pass: re-audit every remaining item against live git log/code, hunting
for the same failure mode. Verdict: item 4 was unique, not a pattern. But two items (5,
frozen agent attestation; 8, Windows behavioral monitoring) were found in a related, more
benign state — fully built and independently tested, just not committed yet, which is
exactly what item 4 would have looked like one day earlier. Both were flagged and,
later in the session, committed on request.

original gap-scan's summary ("only `dm_operation_log` has bounded storage") turned out to
be an oversimplification bordering on wrong: `dm_operation_log`'s coalescing/archival
mechanism is fully built and tested in isolation but has **zero callers in production** —
the same failure shape recurred twice more (two other well-built retention mechanisms,
also never wired). Full per-table report:
`~/work/nemesis-internal/audits/retention-bounded-storage-audit-2026-08-23.md`. Not
committed against — flagged as its own build spec's worth of work, not a Tier-3 fix.

Two new, previously-uncaptured enterprise-parity gaps (vulnerability/patch management,

## Theme 4 — RBAC learning gate (ADR 0026), first code

ADR 0026 committed as a full spec (six decisions: tier semantics, capability→route mapping,
the admin companion-app key-pair design, quiz mechanics, the language-agnostic wire
protocol, platform sequencing). Then, over several handoffs, real code landed against it:

- **`sub_admin` rank** inserted into `roles.py`, proven additive by recomputing all 2,700
  pre-existing (role, endpoint, method) answers against the frozen pre-insertion ordering —
  zero differences, pinned in the import-time canary. This replaced the build spec's called-
  for manual review of 135 registry entries with a check that proves the same property
  continuously rather than once.
- **Capability declarations** (`push_and_run`/`firewall_change`/`approve_enrollment`, all
  still empty — none of the three features exist yet) and `may_with_unlocks()`, keeping
  `roles.py` I/O-free.
- **The unlock schema, quiz engine, and unlock lifecycle** — quiz versioning is a *content
  digest*, not a declared number, so editing a quiz necessarily invalidates every unlock
  earned against the old wording. Proven against a real quiz file on disk (edited, asserted
  the unlock evaporated, restored, confirmed byte-identical afterward).
- **The full admin-approval backend** (four pieces: canonical payload + verification, rate
  limiting/lockout, companion pairing, and the atomic request-consumption state machine) —
  implements a private wire-protocol spec, with two published cross-language test vectors
  and a genuine 16-thread concurrency proof for the state machine's atomic
  `PENDING → CONSUMED` transition. Held for one exchange on a Rule 10 question Window 1
  explicitly declined to decide unilaterally (the code substantially discloses a
  currently-private protocol spec); resolved by the operator — land the code, keep the spec
  private until the full feature ships and is deployed/verified, matching the bar every
  other spec-to-public transition hit today.
- **Startup wiring** for both new tables, landed last since it depended on the store commit.

**Net effect: still no live behavior change.** No capability has an endpoint, so no unlock
grants anything; nothing yet calls the admin-approval verifier in production. This is
additive scaffolding, by design, confirmed at every stage.
