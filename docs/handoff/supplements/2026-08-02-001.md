## YARA auto-update — three rounds of SSRF hardening, each catching something real

Round 1 shipped the mechanism (fetch/validate/atomic-activate) plus cross-platform path
exclusions. Independent review caught a live shadowing incident on this exact
box — `/etc/nemesis-yara-exclusions.conf` was a six-week-stale verbatim copy of the OLD
defaults — fixed by removing the conf file.

Round 2 (M2) added the operator-facing routes, an SSRF guard on the update source, a rate
limit, and settings-write validation. This closed F1 from the route audit but also
created a testability gap: the guard correctly rejects every local-test-server address,
so the fetch-and-activate integration path had no live test. Filed a proposal
(injectable opener, not an env-var bypass) rather than building it inline.

Round 3 — Window 1 built the env-var test-seam override anyway (a defensible call,
documented, not API-reachable), with a 2-entry cloud-metadata denylist. Independent
verification found the denylist covered only its two named addresses while the broader
relaxation silently admitted the entire `169.254.0.0/16` range, including AWS ECS's real
metadata endpoint. Sent back with a proposed fix; Window 1 found that fix would ALSO have
been incomplete (AWS IMDS-over-IPv6 is unique-local, not link-local, so excluding
link-local alone would have missed it). The actual fix — allowlist loopback + IPv4
RFC1918 only, no address enumeration — was verified independently twice (two different
test suites, both run directly, not just read) before landing. This is the shape of
verification this session exists to provide: the fix that shipped is meaningfully more
correct than either of the two prior proposals, including my own.

## Pre-warn page — shipped, then two same-day follow-on bugs

New `/install/windows/<token>/start` page forewarns Windows SmartScreen/UAC prompts
before Windows shows them (can't be done from inside the installer itself — both prompts
gate before a line of it runs). Verified token-gated and non-consuming before commit.

Missing from `_AUTH_EXEMPT`, the page 302'd every visitor to `/login` — unreachable by
its actual audience (people with no dashboard account). Fixed same day; the real access
control (the token) was never affected, only a redundant session-login wall. This became
a new standing route-audit shape in CLAUDE.md: check `_AUTH_EXEMPT` explicitly for any
new public route, because a missing entry passes every other check and still fails
production.

Verifying this page live also surfaced a real, separate finding: installer tokens have no
revocation path anywhere in the product — `revoked` is enforced on read, never written by
any route. Worked around this specific instance with a direct DB update; filed as a
FIX-NOW PUNCHLIST item, not yet built.

## The credential-leak incident

A grep meant to check two specific env keys instead dumped the entire live
`/etc/nemesis.env` into this transcript — real API keys, a password, and an OAuth
secret. Attempted local-transcript redaction; every redaction command re-embedded the
same secrets as new tool-call parameters, making the exposure worse with each attempt.
Abandoned redaction as structurally self-defeating and recommended rotation instead, per
the operator's own established precedent for this class of incident. Rotation is blocked
on my end either way — external services need the operator's own console access, and
Pi-hole needs interactive `sudo` unavailable in this shell. A pre-rotation snapshot is
taken and waiting. **Operator owns this; not yet done as of closeout.**

## Process discipline added to CLAUDE.md today

- Window 2 confirmed as backup git-writer for private modules (not a one-off).
- A new, distinct hazard: shared-index staging. Found live when a plain `git commit`
  swept an unrelated 254-line change into a docs commit because it had been staged in an
  earlier step and never un-staged. Fixed via `git reset --soft HEAD~1` (verified unpushed
  first) and re-split correctly. Standing fix: stage-and-commit as one atomic step, never
  leave anything staged across a turn boundary.
- Fifth route-audit shape: check `_AUTH_EXEMPT` explicitly (see pre-warn page above).
- Two VM-fleet rules: `KEEP`-naming protects a clone from any cleanup pass regardless of
  appearance; identify VMs by host ARP or in-guest data, never the VirtualBox DHCP leases
  file (a stale lease pointed at the wrong running clone during today's fleet audit —
  read-only that time, would not have been recoverable one step later during a write).
