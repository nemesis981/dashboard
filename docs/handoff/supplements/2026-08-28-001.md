## Process notes worth carrying forward

- The gap-inventory task is a good template for future "what's actually left" audits: run
  the data-gathering in parallel background forks, synthesize once, restructure on
  operator feedback without relaunching the forks that already covered the needed ground.
- The mid-flight commit split (item 9 above) is a concrete instance of the shared-working-tree
  hazard CLAUDE.md already warns about — content changed under a window between reading a diff
  and committing it. The fix pattern (`git reset --soft` + hunk-level `git apply --cached` +
  manual line-anchored patches when hunks won't split cleanly by context) is now proven live,
  worth keeping as a reference for the next time this happens.
- Independent re-verification of another window's handoff claims (item 10) caught nothing
  wrong this time — every number matched — but the discipline is what makes that a real
  finding rather than an assumption.
