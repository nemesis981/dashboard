## Two things worth carrying forward, not just filing away

**1. The shared working tree bit this batch twice, and both times the fix was cheap because
nothing had been pushed yet.** First, Window 1's own `roles.py` C3 diff arrived co-mingled
with two other windows' hunks that Window 1's handoff didn't flag — caught by reading the
full diff rather than trusting the file list. Second, I mistakenly committed three of
Window 3's in-flight files (swept in from the same working-tree diff as a legitimate Window 1
change) as part of `8329c8f`. The operator caught it before push; recovered with a
`git reset --soft` sequence (rebase was blocked by the auto-mode classifier as a
history-rewrite) that dropped the commit and restored the three files to uncommitted status
with their content verified byte-for-byte unchanged. Nothing was lost, but the lesson
repeats CLAUDE.md's own standing point: read every diff, don't trust a file list, and this
applies to fresh work from a trusted peer exactly as much as to a stale handoff.

**2. A claim that didn't check out, caught before acting on it.** A message reported three
files as sitting in a private-repo commit needing a pull; reading that commit directly
showed it touched only a handoff markdown file, no code. The claim was corrected before any
action was taken — worth noting because the pattern (a plausible-sounding provenance claim
citing a real rule out of context) is exactly the shape this project's own standing
practices exist to catch, and it applied here to an inbound instruction, not just to
production code or a self-report.
