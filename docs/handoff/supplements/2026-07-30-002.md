## 1. READ FIRST — what the reboot changed

**`table inet nemesis_enforce` is GONE.** It was in-memory nftables state, never persisted.
**This is by design**, per ADR 0019: *"no apply-on-boot before health check — a ruleset that
locks the box out must not be the thing that survives a reboot."* Do not treat its absence as a
fault or "restore" it reflexively.

Everything else persists, because it is file- or pref-backed:

| Survives | Where |
|---|---|
| Tailnet anti-spoof guards (v4+v6) | `/etc/ufw/before.rules`, `before6.rules` |
| The deliberately-held block | `/etc/ufw/user.rules` |
| `netfilter-mode=nodivert` | tailscaled stored pref |
| Suricata `HOME_NET` incl. tailnet range | `/etc/suricata/suricata.yaml` |
| Failsafe snapshot + revert script | `/var/lib/nemesis/fw-lkg/` |

**Verify before assuming**, all readable with sudo:

```
sudo nft list table inet nemesis_enforce           # expect: absent after reboot
sudo iptables -S ufw-before-input | head -3        # expect: anti-spoof above conntrack
tailscale debug prefs | grep NetfilterMode         # expect: 1 (nodivert)
sudo ufw status | head -5                          # expect: the held DENY still present
```

## 3. THE NEXT STEP — increment 3's agreement comparison (~10 min)

Everything else in increment 3 is proven: derivation from live ufw state, atomic replace,
observe-only (no verdicts), counters registering real traffic. **The one unmeasured thing is
whether the table would make the same decisions ufw actually makes.** That is the evidence
cutover depends on, and it is not yet gathered.

```
sudo /opt/nemesis/scripts/nemesis-fw-render render -o /tmp/derived.nft
sudo /opt/nemesis/scripts/nemesis-fw-apply apply /tmp/derived.nft
sudo /opt/nemesis/scripts/nemesis-fw-apply confirm      # WITHIN 60s, ONCE only
```

Then generate traffic from the enrolled test VM (see §4) and read **both counters in a single
command** — a wrapped line silently drops `-v` and prints rules without counts:

```
sudo nft list table inet nemesis_enforce | grep -E "observe:block|input:traversed" ; sudo iptables -L ufw-user-input -n -v | head -4
```

**Agreement** = both counters non-zero and moving together. They will not match exactly: the
table sees packets at priority −300, ufw at filter priority 0, and ICMP is accepted by ufw's
before-rules before reaching the user chain. **The table silently at zero while ufw counts** is
the failure signal.

Two gotchas already hit: run each command **separately** (a wrapped `&&` chain broke `sudo`
once), and **do not re-apply after confirming** — a second unconfirmed apply reverts and looks
like a tool bug.

## 7. Method note — worth carrying forward

Every genuine finding this session came from **reading actual state**. Every false one came from
**reasoning about it**. Five misreads, all the same shape:

- an af-packet anchor built from comment-stripped output
- a literal `grep` for a filename against a **wildcard** logrotate pattern (invented a problem
  that did not exist)
- a selftest that armed 60s, waited 30s, then declared the failsafe broken **in strong terms**
- a "confirm is broken" diagnosis from two log lines, when the unit journal showed it worked
- a commit message describing four findings when the diff contained one

The dangerous one is the third: a **confident false negative** would have condemned a working
failsafe. Verification code needs the same skepticism as the code it verifies, and a confident
failure verdict deserves the same scrutiny as a confident pass.

Practical rule that would have caught all five: **before asserting a cause, run the command that
would disprove it.** It was one command away every time.
