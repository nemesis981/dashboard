# Supplement — 2026-08-26 (Window 2)

Continuation of the pre-reboot session (`2026-08-25-001.md`). 23 commits landed and pushed
across the tail of 2026-08-25 and all of 2026-08-26, almost entirely independent verification
of Window 1's and Window 3's work, with several real bugs caught before landing and a few
caught in what had already landed.

## What actually happened

The bulk of the session was reviewing Window 3's build-out of the `email_security` module
through Stages 2.6–5 (email account storage, attachment detonation, link detonation, and
quarantine/notification UI), plus two unrelated fires: a real production false-ransomware
incident from the day before, and an RBAC error recorder that had been silently recording
nothing for an unknown period.

**The pattern that mattered most**: several findings this session were not about whether the
new code worked, but about whether the *verification* of the new code was asking the right
question. Two stand out:

1. **The module-load bug (`56fd2b2`).** `email_security`'s `get_routes()` used a relative
   import that fails under `modules_loader`'s loading scheme. The entire module — not just
   its routes — silently never loaded in production, for the whole span of Stages 2.6
   through 5.1. Every one of 424 passing tests missed it because none of them ever called
   `get_routes()`; they all imported the module's internals directly. "The suite is green"
   said nothing about whether the module actually loaded. Caught only because a *different*
   piece of work (a new load-time RBAC gate) required driving the real loader for the first
   time.
2. **The stash/measurement incident.** Window 3 tried to answer "did my change cause this
   test failure?" with `git stash push` + `pop` — a state-moving command in a shared tree
   with a shared stash stack. The pop applied a different window's unrelated stash instead
   (documented in `69687c7`), and separately, the push itself silently hadn't taken, so the
   "before" measurement still contained the change being tested. The change was compared
   against itself and wrongly reported as pre-existing (`test_roles.py` 157/1). Both the
   specific stash hazard and the general lesson (a diagnostic's own output needs the same
   "prove the premise" scrutiny as production code) are now standing CLAUDE.md rules
   (`69687c7`, `bab4cbc`).

Both are now written into CLAUDE.md as standing practice, not just fixed in place.

## Verification discipline this session

Every commit was independently verified before landing — re-running suites is the floor, not
the standard applied. Where the claim was safety- or security-critical, verification went
further:
- **Ransomware canary fix**: reverted the fix in a live copy and watched the actual incident
  reproduce (plant paths resolving to the real `/home/<user>/...`) before trusting the fix
  removed it.
- **Module-load fix**: drove the real `modules_loader` against every real discovered module
  through the actual `dashboard.py` Flask app — not a mock — and confirmed the new routes in
  the live `url_map`.
- **RBAC recorder fix**: reproduced the exact `connect("core")`/`connect("dashboard")`
  control pair through the real recorder machinery, after having been burned once already
  that day by re-testing the same wrong premise instead of asking a different question.
- **Link-detonation redaction**: independently re-ran the actual corpus-validation numbers
  (45,311 URLs / 55 addresses / 0 residual) against the real burner-mailbox corpus once the
  privacy concern that had initially stopped me from doing so was resolved.

Two false claims from peer review were caught and retracted the same day they were made: an
RBAC-registry gap that turned out to be testing the wrong endpoint-identifier format, and the
"pre-existing" test failure above. Both retractions are recorded in the private mirror with
the original wrong text preserved, not deleted — Window 3's framing, and the right one: how
an error happened is worth keeping.

## What's genuinely new for the product

`email_security` now has two live, load-bearing routes (quarantine list + release), a
dashboard card, tiered always-notify quarantine notifications, and a fully-built (mock-tested)
link-detonation pipeline awaiting only the corpus/gateway-VM work needed to measure detection
efficacy — deliberately not conflated with validating that the engine works, per the
project's own D9 precedent. All of it ships behind `enabled_by_default: false` and
`confirmation_required: true` in the manifest, so none of it is live for an existing install
without explicit opt-in.

`modules_loader.py` gained a structural safety net that applies to every future module, not
just this one: a route whose endpoint isn't in `roles.ROUTE_MINIMUMS` now fails to register
(404s) rather than only logging a warning. The RBAC recorder bug fixed the same day is exactly
why that mattered — a warning had already gone unread for an unknown length of time.
