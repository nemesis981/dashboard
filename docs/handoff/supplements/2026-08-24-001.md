## Themes

`keyprotect` clause (§6 step 2 said "store via keyprotect"; D3's actual decision is the
admin private key lives on the phone, appliance never holds it — satisfied-by-not-applying)
was flagged by Window 1 after it caused a real misread of the build sequencing. The
`attempts`-counts-passes-not-tries wording was flagged by Window 3 at nearly the same moment
I'd already fixed it independently — good corroboration, not wasted effort. Both landed as
small, isolated doc commits (`950e0d3`, `31c76e1`).

**2. A fourth standing CLAUDE.md practice, from a real cross-window pattern.** Three
consecutive days of the same bug shape — a new branch or default nothing exercises, shipping
green because every test happened to take a different path (`capabilities._conn()`, role.js's
missing `sub_admin` entry, the unwired unlock gate, a same-day near-miss). Written up as its
own checkable item alongside the existing three (`af4183f`).

**3. Window 3's RBAC training-UI batch — the first big landing.** 8 files per their handoff
prose, actually 10 (caught by diffing against `git status`, not trusting the count — flagged
but not worth interrupting them over). Split into 3 dependency-ordered commits, each
live-verified from a fresh `origin/main` worktree rather than trusted from their report:
role.js's `sub_admin` gap, a real bug in `capabilities._conn()` (called a function —
`data_manager.get_data_manager()` — that does not exist; every test passed an explicit `conn=`
so the actual production default-argument path had zero coverage), and the training UI itself.

**4. Two docs landed for ADR 0028 (email security gateway)** — the ADR public, the build spec
private per Rule 10 D8, both already resolved by the operator in-document.

**5. Window 1's four Stage-0-prerequisite handoffs — the largest and most consequential
piece of today.** Worked through in dependency order (Stage 5 → commit 1 → commit 2b →
meminject) via isolated worktrees. Caught a real stale-claim bug before it reached
`origin/main`: commit 1's handoff said `tasks.py` was safe to copy whole ("+147, all mine"),
but the live file had grown to +507 lines merging commit 1's classification work AND commit
2b's admin-approval verification together — copying it into commit 1 alone would have shipped
a crashing `self_test()`. Window 1 fixed it with a proper two-patch split; independently
re-verified rather than trusted a second time (sha256 chain-check, all 7 suites re-run).

**Then a genuine process failure on my side**, not a peer's: all four commits were built in
detached-HEAD worktrees and the worktrees removed immediately after committing, without ever
creating a branch ref. All four became unreachable dangling objects — invisible to
`git log`/`push`, one `git gc` away from being destroyed. Reported them as "held for push
confirmation" when nothing was holding them at all. Caught by Window 1's independent check,
not mine. Fixed (`git branch`, re-verified reachable), pushed, and saved as a standing
process memory — branch before `git worktree remove`, every time, no exceptions.

**6. Bringing the shared `/opt/nemesis` checkout current wasn't the clean fast-forward it was
assumed to be.** Two genuine pieces of other windows' in-progress uncommitted work would have
been silently discarded by a plain `git pull`: Window 1's held GUI-findings buffer in
`agent.py`/`agent_errors.py`, and Window 3's untracked quiz-wording revision. Used
stash→pull→pop for the tracked files (clean auto-merge, verified — not assumed — by grep for
conflict markers and grep for both bodies of code) plus a manual backup/restore for the
untracked file (verified digest-safe: the graded fields were unchanged from origin, so no
earned unlock was invalidated by preserving the revision).

**7. Stage 0 step 1, and a contradiction that turned out to be a stale offhand remark.**
Session realms + nemesis-fwd's new interface-scoped deny/allow op, reviewed and verified in
full before committing. The operator's task description said Window 1 flagged
`NEMESIS_DOOR_SECRET` as needing to be added to `ENV_WRITE_ALLOWED_KEYS`; Window 1's own
message said the opposite, with real security reasoning (a compromised dashboard must not be
able to mint its own door secret — that would defeat the LAN/TLS realm split for everyone).
Verified the live code matched Window 1's stated intent, did not add the key, flagged the
contradiction rather than silently picking a side. Window 1 later traced it to an early
offhand inference, superseded by their own later analysis, never explicitly retracted —
same "prose outliving its verification" shape as the `tasks.py` line count.

**8. A live production gap, found and closed same-day.** `scripts/nemesis-cert-renew` and its
systemd timer were running on the real box — timer active, hours from its next fire — with the
source existing in no repository. A redeploy from `origin/main` would have left the timer
firing at code with no upstream, the failure surfacing ~30 days later at cert-expiry, the
furthest possible point from the cause. Verified the installed binary was byte-identical to
the untracked source before committing. Landed alongside two smaller, deliberately-unwired
Stage-0 prep pieces (`core/rp_identity.py`, `alert_manager/local_port_watch.py`) and a small
self-caught test fix, each its own commit.

**9. Window 3's quiz revision, protected on request.** Flagged as newly vulnerable to being
clobbered once the earlier blocked pull completed. Re-verified it was the genuine reviewed
version (not the placeholder) and still digest-safe, committed and pushed immediately with no
window for loss.
