## Two same-night regressions — both caught and recovered same-night

Full evidence-first accounts are in the worklog; summarized here because they're the kind
of thing that shouldn't need re-discovering later.

1. **A span-replace edit briefly clobbered the `_RECOVERY_*` constants.** A whitespace-fix
   edit used a find-to-next-`def` span replace instead of an exact-match `.replace()`; the
   span swallowed four constants sitting between the two functions. Caught by Window 2's
   independent review (an AST check for undefined names) before it reached any commit.
   Root-caused, restored verbatim from an earlier backup, closed with a whole-file
   unresolved-name sweep across all 172 functions rather than re-checking only the touched
   ones.
2. **`dashboard.py` reverted to byte-identical-with-HEAD during a commit-splitting attempt.**
   Window 2 was building the file up incrementally for fine-grained commits and, after
   landing one piece, failed to restore the rest of the uncommitted work before continuing —
   transiently dropping twelve functions from the working tree (never from git; no commit or
   stash ever held the broken state). Caught within minutes by a routine grep, restored from
   a scratchpad backup, re-verified against all four live checks (batch generation,
   regeneration disjoint set, `/setup` issuance, live HTTP regenerate).

**Process lesson, adopted going forward:** after any structural edit, run a whole-file
check and diff the unresolved-name set against a known-good baseline — targeted
verification (checking only the functions believed touched) cannot see collateral damage
outside that set. And: `dashboard.py`'s hunks interleave too heavily across features for
fine-grained commit-splitting to be safe — hand it over as one commit going forward.
